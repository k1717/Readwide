# Readwide 1.0.22 development changes

Changes since 1.0.21.

## TXT indexing and page navigation

- `ReaderLargeTextExactPageIndexController` reads the configuration before marking an index as building. It catches submission rejection and worker-start memory or stack errors, including errors during worker setup. If the result cannot be delivered, it clears the pending request.
- `LargeTextExactPageIndexState.failCurrentBuild` invalidates only the matching pending generation and does not allocate new anchors. A task queued before submission failed cannot publish afterward. Late failure reports leave newer or completed indexes intact. A later request can retry the same signature; there is no automatic retry loop.
- `LargeTextAnchorMath` compares the top-row character directly with the page anchor on a backward tap. This removes the eight-character dead zone after blank or short rows: the first tap returns to the current page start, and the next moves to the previous page.
- Regression sources cover rejected submissions, synthetic memory and stack startup errors, retained tasks, same-signature retries, replacement ownership, short rows, queued backward steps and integer edges. The earlier navigation oracle is unchanged except for the backward dead zone correction.

## TXT task startup

- `TaskSubmission` wraps submitted work in a cancellable task. TXT loading, count/navigation searches and view highlights cancel retained queued work when executor startup throws a runtime, memory or stack error.
- `ReaderFileLoadController` retires the failed load generation, stops its spinner and leaves the error visible. Search controllers release only the matching request and preserve the previous match position. Highlight failures wait for a changed text, query or visible range rather than retrying on every draw.
- Regression sources cover retained rejection, startup memory/stack errors, retries, newer-request ownership and highlight retry boundaries. Search matching and page movement calculations are unchanged.

## Saved data and backup ownership

- `BookmarkManager` publishes loaded bookmarks or reading states only after the complete collection parses. Read failures are no longer converted to a missing file. Each store remains protected from writes until a later read succeeds; missing files are valid empty stores.
- Export and import require both stores to load, including replacement imports whose rollback needs the original data. Path-prefix replacement also checks both stores before changing either. No storage schema or saved-coordinate migration is added.
- `SettingsBackupViewModel` assigns the global backup lock to a specific task. Rejected work is cancelled before startup; work already running retains ownership until commit or rollback finishes. Cancelled or duplicate tasks cannot perform writes, publish a result or release another task's lock.
- Regression sources cover partial JSON records, invalid UTF-8, missing collections/files, transient read errors, write suppression, successful retries, retained backup work and an executor reporting failure after work starts. The existing manual-bookmark save-feedback limitation remains separate.

Cursor iteration checks cancellation and closes partial results; only the active request can complete, once. - `SettingsFolderAccessController` shows registered folders under Settings > Security and folder permissions, reusing the rounded settings panel/buttons. - Failed single/batch deletes, delete-plan preparation, clipboard transfers, rename and new-folder creation on shared internal storage and detected SD/USB roots offer the folder picker. Paste preflight also offers it when the destination is not writable. No raw path is converted to an opaque provider ID, and authorization does not replay an operation. Discovery retains a short cache inside repeated rebuilds.
- `SharedStoragePaths` checks canonical path boundaries for permission offers and deduplicates readable roots. `MainDrawerController` supplements `/storage` and app-files discovery with mounted/read-only directories from Android's [volume API](https://developer.android.com/reference/android/os/storage/StorageVolume#getDirectory()) on API 30+. Inaccessible or provider-only volumes still require the system picker; discovery does not grant access.
- `SafStorageAccess` distinguishes persisted read-only access from read/write access. `SafDocumentEntry` retains deletion flags and whether size metadata is known. `SafDocumentDeletion` checks the selected URI, excludes the tree root, re-queries metadata and deletion support, calls `DocumentsContract.deleteDocument`, then verifies absence. Unknown provider outcomes remain unconfirmed. These checks do not lock concurrent writers or make a provider's deletion reversible.
- `SafOperationViewModel` owns serialized mutations, cancellation, clipboard selection and one completion result through configuration changes. Tasks retain application context and captured document/tree values, not an Activity. `SafStorageAccess` pins source and destination grants independently of the remembered tree. Each browser pins its own tree until the model is cleared or switches trees; changing the remembered folder cannot release another browser's access. Recreation observes the same pending result.
- `SafBrowserActivity` contains provider-copy runtime, memory and stack failures during archive opening. Only the matching live request clears pending state or opens the result; failure resets its debounce so reopening can retry. Document/archive submissions use `TaskSubmission` to cancel retained queued work after startup rejection.
- Cancellation replaces only generic failure messages, preserving committed, partial and uncertain results. Creation/rename confirmation failures and native-move resource errors retain an unconfirmed outcome after a mutation may have occurred.
- Provider metadata queries reject loading/error cursors before and after traversal. Directory queries contain startup and worker memory/stack failures; rejected queued tasks cannot publish later. Deletion probes absence even after a false or failed mutation reply. A failure after mutation starts cannot claim that nothing changed. Create/rename calls retain uncertain results when replies fail or return no URI; rename rechecks source metadata and parent membership after collision lookup. Failed-copy cleanup retains uncertainty when a create request may have succeeded without returning its URI.
- Rename verification permits an updated MIME type and document ID. It still checks the requested name, file/directory kind, known file size and destination membership. Android's [filesystem provider](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/core/java/com/android/internal/content/FileSystemProvider.java) permits MIME changes when renaming an extension. Size changes or lost known size remain unconfirmed, and no rollback renames an uncertain result.
- `SafBrowserActivity` binds action/confirmation callbacks to their dialog, tree, parent and query generation. It consumes an accepted callback before dismissal; callbacks from dismissed/replaced dialogs cannot dismiss a new one or select an old file under a new tree. Navigation, pause and destruction dismiss the owned dialog without cancelling an already-started retained operation.
- `SafOperationViewModel` retains clipboard selection and its source-tree pin after retryable paste outcomes. Completed transfers, retained-source outcomes and uncertain outputs consume the captured selection so they cannot remain queued for accidental replay. A completed older task does not clear a newer selection.
- `SafStorageAccess` stores a set of registered tree URIs and per-tree labels, separately from the last selection. The old single-tree value appears in the list immediately; the first registry edit migrates its URI and label together. Registration, selection, explicit removal and pin/unpin share a lock. Adding a folder retains earlier grants, and losing permission does not discard its registration. Revocation is blocked for pinned trees; failed release keeps the entry. Only registered tree grants are exposed for removal, and files are untouched. Corrupt registry state fails closed rather than becoming an empty list. Unregistered temporary grants retain last-pin cleanup. Folder registrations and grants remain outside settings backup.
- `SafDocumentOperations` checks tree scope, persisted permissions, provider capabilities and selected metadata before create/rename/transfer. Complete inventories reject loading/error cursors, cycles, partial/virtual documents and excessive depth/count. Copies create new names only. Each closed output's metadata is captured before byte comparison and checked afterward against that same snapshot. After the source inventory check, acceptance rechecks all copied files, exact child membership and the root's destination parent. Directory timestamps changed by the copy's own child creation remain valid. Provider-native moves recheck the source after collision lookup and verify both destination membership and departure from the old parent.

Fallback file moves recheck the source parent after destination verification; `SafDocumentDeletion.deleteCopiedSource` also rejects current remove-from-parent, partial and virtual flags in its metadata query. Explicit deletion keeps its existing semantics. A fallback folder move, a multi-parent document or a source whose deletion cannot be confirmed retains its original alongside the verified copy. Failed-copy cleanup removes only unchanged created files and empty created folders still in their captured parent. No recursive cleanup removes unexpected children. Provider check-to-mutation races and same-metadata changes remain possible.
- `FileDeletionPlan` captures a no-follow identity/metadata/membership snapshot on the worker before confirmation. Removal uses a fixed postorder list, validates the whole plan first and rechecks each node after progress callbacks. New children do not become deletion targets; changed or unidentifiable plans fail closed. Pause, destruction, dismissal and a changed selection invalidate the offer.
