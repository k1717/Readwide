# Focused RAR selected-fallback validation - Readwide 1.0.20

This report covers the selected-entry fallback routing fix only.

## Change

`RarArchiveReader.extractSingleEntry` now tries the existing
`Rar3LogicalSolidArchiveExtractor` before reporting an ordinary native failure or
unavailable backend. This connects eligible AES/split RAR3/4 solid selected entries
to the already implemented bounded decoder. Existing eligibility, primer checks,
password handling, explicit file boundaries, CRC checks and output guards remain.
Typed native cancellation and a set thread interrupt remain terminal before any
fallback. No decoder algorithms, TXT paging, shared reader logic or dependencies
were changed.

## Executed host checks

Windows, OpenJDK 21.0.10 (Android Studio JBR), JUnit 4.13.2. The isolated workspace
directory is `rar-selected-audit`. `javac` compiled the actual archive Java sources,
including `ArchiveSupport`, `RarArchiveReader`, `RarLibarchiveFallback` and the RAR
decoders. The JNI boundary was replaced only in the host compilation by a controlled
`LibarchiveNativeBridge` substitute. It can report unavailable or throw a native
IOException, password-required exception, typed cancellation or thread interruption.
Unrelated ZIP creation/native Zstandard APIs and Android annotations were stubbed.
`FileOperationProgress` was compiled unchanged. No Gradle, Android/APK verification
build, native decoder binary or downloaded executable was run.

Declared Java dependencies and JUnit were downloaded from Maven Central into host
scratch. The project dependency configuration was not changed. Compilation passed;
the host-only varargs stub produced one warning, alongside existing deprecation notes.

| Check | Result |
|---|---|
| Original source, initial 10 public-route cases, native unavailable | 4 valid AES/split solid cases failed; 6 negative cases passed |
| Original source, same 10 cases, injected ordinary native IOException | Same 4 valid cases failed; 6 negative cases passed |
| Fixed source, final 11 public-route regressions, native unavailable | 11 passed |
| Fixed source, same final 11 regressions, injected ordinary native IOException | 11 passed |
| Additional host-only native boundary cases | 6 passed |
| Original upstream fixtures through public selected extraction | 9 files passed |
| Derived AES/split wrappers around real RAR3/4 solid compressed members | 6 cases passed |

The final public regressions check AES, split, AES+split, a stored member between
compressed entries, primer and target CRC failures, preserving an existing output,
removing new partial output, missing/wrong passwords, a missing volume and pre-set
interruption. Native-boundary checks establish whether the backend was called and
verify ordinary IOException fallback, unavailable-backend behavior, supplied/missing
password handling, typed cancellation without an interrupt flag and thread interruption.

The 11 portable regression methods are in `Rar3SelectedSolidFallbackTest.java`.
Host-only injection/fixture tools remain in workspace scratch and are not production
classes. No test failures remain in the final focused runs. No checks in this report
were skipped; Android/native-device interoperability was outside the executed scope.

## Upstream fixtures and limits

Fixtures were pinned to these repository revisions and kept only in workspace scratch:

- [rarfile](https://github.com/markokr/rarfile/tree/d2f7df6fc843dae356fd6b0a85971dc36fd6e757/test/files):
  `rar3-solid.rar`, two 2,048-byte files, CRC32 `c5b7e6a2`; both passed.
- [SharpCompress](https://github.com/adamhathcock/sharpcompress/tree/2cba09eba4ae400756933807ee5b0aae56bd4fa7/tests/TestArchives/Archives):
  `Rar.solid.rar`, three regular files (15,498 / 45,056 / 40,372 bytes), all passed;
  `Rar.multi.solid.part01.rar` through `part06.rar`, three regular files, all passed.
  The multivolume archive actually has the **RAR5** signature, despite its filename;
  it is a neighboring routing safeguard, not evidence for producer-generated RAR3 split support.
- [libarchive](https://github.com/libarchive/libarchive/blob/7e9bfb0469afa0bb7362a56e79be87bedcb91946/libarchive/test/test_read_format_rar.c#L743):
  `test_read_format_rar_ppmd_lzss_conversion.rar.uu` was decoded as data. Its single
  241,647,978-byte member passed size, CRC32 `f72b4477`, and the upstream expected
  trailing text. This demonstrates repeated PPMd/LZSS switching in one real member,
  not an encrypted multi-member solid combination.

All nine original selected outputs were checked against declared lengths and CRCs.
The upstream test's trailing text was independently checked for the conversion case.

For each of the two real RAR3/4 solid archives, the existing producer-compressed bytes
were rewrapped as AES-only, split-only and AES+split containers. Selecting the final
solid member after one injected native failure matched the original extracted bytes
exactly in all six cases. These are **derived test fixtures**, not independently
producer-generated encrypted/split archives. They do not verify the entire format
cross-product or native Android loading. No original or derived external fixture,
downloaded dependency, decoded executable payload or host class was added to the
project or its source ZIP. Decoded `.exe` entries were treated only as bytes.

Other audited ZIP/7z routing gaps, generic RAR VM, EGG LEA and encrypted-solid EGG
remain outside this focused change. TXT exact pagination and related shared logic
remain untouched. No GitHub publication was performed.
