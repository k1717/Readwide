# Readwide 1.0.16 development changes (vs 1.0.15)

## Unified built-in browser fallback

- The raw-`File` browser retains its existing platform permission handling. The new compatibility route is an API-independent persisted SAF tree selected by actual directory-enumeration capability rather than by a hard-coded OS or OEM branch.
- Storage diagnostics now report whether raw directory enumeration is actually usable instead of assuming that a granted permission guarantees it. Diagnostic lines contain no user path or filename.
- A `null` directory listing is an access failure, not an empty directory. Initial loads and refreshes share the unavailable-location result and avoid caching a false empty-folder signature.
- The second compatibility path is API-independent SAF rather than another OS-version branch. `SafStorageAccess` retains and validates a user-selected tree; `SafBrowserActivity` queries child documents by document ID, preserves its own navigation stack, and routes readable files through the same URI viewer policy as Open file.
- A persisted SAF tree suppresses repeat raw-storage permission prompts on later launches. The drawer exposes one `Internal Storage` entry: without a tree it uses the authorized raw browser, while a persisted tree makes the same entry provider-backed and suppresses duplicate raw Internal/SD/Downloads rows.
- SAF mode is intentionally read-oriented in this stage. Folder navigation, sorting, filtering, PDF/EPUB/TXT/document/image opening, and cached archive opening are supported. Raw-path-only multi-select, copy/move/delete, folder-wide search, and cover-thumbnail generation are not falsely exposed for provider documents.
- SAF directory queries and archive URI copies no longer share one executor. Provider browsing remains responsive while a large archive is copied into `opened_files`; navigation invalidates and cancels the copy Future, and the bounded shared URI-copy loop observes interruption before another provider read. An obsolete completion cannot retain the open latch or launch a viewer.
- `FileUtils.copyUriToLocal()` now uses a fair `ReentrantLock` acquired with `lockInterruptibly()` instead of a synchronized method. Cache prune/commit remains serialized, but a cancelled worker waiting behind another provider copy exits before entering the critical section.
- The SAF file-open path has the same short duplicate-open gate as the raw browser's intent path, applies the shared hidden-file preference, and keeps directory-query/archive-open progress as separate state.
- `SafStorageAccess` centralizes optional one-shot-document read persistence and read/write-with-read-only-tree fallback. This removes three subtly different permission blocks from `MainActivity`, `ThemeEditorActivity`, and `SafBrowserActivity`.

## Archive image export, spread, and browser thumbnails

- Archive-backed `ImageReaderActivity` pages can copy their original extracted bytes to `MediaStore.Downloads`, legacy public Downloads, or a Storage Access Framework destination. Export naming is normalized by pure `ImageExportName`; Activity-result source state survives recreation and partial failures are cleaned up.
- Optional archive spreads use `ArchiveImageSpreadMath` and allocation-free `ArchiveImageSpreadDrawable`. The gate is archive source + landscape + preference + two decoded pages whose height is at least 1.10 times width. RTL changes physical slots, while wide/square/final pages stay single.
- Spread runtime preparation accepts a cache-rejected but still displayed first bitmap, explicitly prepares `current + 1` on enable/landscape rotation, and classifies static WebP/GIF candidates by the actual decoded drawable instead of excluding them by filename. `ArchiveImageSpreadNavigator` reverses the actual mixed-screen path rather than inferring history from asynchronously learned ratios.
- Ordinary loose-image preview is raised to a 2x display target/24MP ceiling. `ImageDecodeHelper.decodeArchivePreview()` uses a denser 3x display target with the same 24MP ceiling for archive-backed pages; speculative neighbor prefetch remains 1x/8MP and explicit zoom detail remains 4x/48MP.
- A low-resolution neighbor bitmap can still appear immediately on a page turn, but the current archive page is then upgraded in place to the archive-preview profile. The focused spread-companion request uses the same profile and pins an oversized prepared bitmap outside the LRU until the cache or visible `ArchiveImageSpreadDrawable` assumes ownership.
- The archive-page Save destination chooser alone is clamped to a compact 320dp maximum width; all dialogs retain a 16dp minimum screen-edge margin.
- `ImageReaderActivity` now expires only its viewer Activity after ten continuous minutes fully stopped in the background. It also finishes immediately when Android reports background memory pressure. Reading state is flushed in `onPause`, short switches/configuration changes remain valid, and saved-instance restoration carries a wall-clock guard so an old task cannot reopen a partially released bitmap/archive graph after process death.
- The image-viewer expiry state is declared before the `backgroundExpiryRunnable` field initializer that captures it. This avoids Java's illegal-forward-reference compilation failure without changing the expiry behavior.
- `FileAdapter` applies one persisted thumbnail toggle to the normal and Recent lists. The square 40×40dp preview sits in a 42×42dp container and uses each adapter's 12 MiB memory LRU, while `FileThumbnailLoader` globally limits real work to two concurrent background decodes. The OFF state retains the same 42dp horizontal slot around its 28dp icon, preventing the text column from shifting when the toggle changes.
- Thumbnail sources now include loose images, a folder's first loose image (or first supported book file), and first images from ZIP/CBZ, RAR/CBR, 7z/CB7, standard `.001` split starts, ALZ, EGG, and TAR/CBT-family archives. PDF page 1 through platform `PdfRenderer` and raster EPUB covers resolved from EPUB 3/EPUB 2 package metadata remain supported. Generic icons remain the fallback for encrypted, malformed, SVG-only, or unsupported sources; a true grid remains out of scope.
- `FileThumbnailLoader` persists successful previews as PNG in `cacheDir/file_thumbnails_v1`; the internal identity is advanced to `readwide-thumbnail-v2`. The SHA-256 key covers canonical path, source length/mtime, requested size, and format version. Cache hits refresh access time; an initial and periodic oldest-first trim bounds storage to 64 MiB or 1600 files.
- Disk-cache commits flush and sync a same-directory temporary file, then atomically replace the target with `android.system.Os.rename()`. Trimming is serialized, removes abandoned temporary files, and skips keys currently owned by a per-source reader/writer. The previous valid PNG is therefore not deleted before a new write is known to be complete.
- Thumbnail work is deduplicated per adapter generation/key. A two-worker `ThreadPoolExecutor` uses a bounded 96-item queue; full dataset replacement clears obsolete queued work immediately, and temporary saturation requests a delayed row rebind. Completion posts through an adapter-owned main handler instead of the initiating row's potentially detached View queue.
- Failed requests have a generation-scoped 60-second retry deadline rather than a permanent negative-cache entry. Directory memory entries expire after 30 seconds and are invalidated on full folder reload, covering child-cover replacement on filesystems that leave the parent mtime unchanged.
- Negative retry bookkeeping is capped at 512 current-generation records, with expired records removed first, so a very large folder of damaged or unsupported files cannot grow adapter state without bound.
- Source length/mtime is captured before decode and verified afterward, so an in-progress copy/replacement cannot publish a partial bitmap under stale metadata. Declared zero-byte, unknown-size, or over-128 MiB EPUB/archive cover entries remain rejected before optional preview decoding or extraction.
- Folder and archive cover selection tries up to eight naturally sorted candidates, allowing a damaged/unsupported first image to fall through. Zero-byte and oversized extracted entries are rejected, JFIF/WBMP/DNG/HEIC/HEIF/AVIF are recognized where the platform decoder supports them, and reference-counted per-key locks keep normal/Recent disk-cache writes serialized while waiters exist.
- The folder overflow popup derives its width from the widest localized normal/alternate label, capped to the live content width. Its rows can grow vertically when an exceptionally long translation reaches that cap. Hidden-file visibility now uses localized on/off labels rather than a separate fixed-width O/X column.
- The main overflow remains fixed beside the **Readwide** title in Home/Recent mode. That Home variant contains the hidden-file and cover-thumbnail state toggles but not the folder-only **New folder** action; toggling hidden entries reloads the visible Recent list.
- The multi-selection overflow measures its count title and current action set instead of using a fixed 168dp width. Every action row is wrap-content with no ellipsis or arbitrary label-length threshold, so Select all, Share, Extract archive, and longer localized actions remain complete.
- The image-viewer overflow popup uses the same measured-width and unrestricted wrap-content-row behavior, based on the subset of actions available for the current image. It no longer assumes 210dp or repeats that constant in its anchor offset.
- The main Open-file launcher and theme background picker catch providers that reject persistable URI grants. Their valid one-shot read permission remains usable for the current operation instead of producing a `SecurityException` crash.

## Dedicated EPUB default font

- `PrefsManager` owns a separate `epub_font_family`. One-time migration distinguishes a missing legacy preference from an explicitly selected `default`, so existing System Sans users are not reset to the book font.
- Settings and `DocumentFontDialogController` write the same preference; the document theme signature includes it so returning from Settings refreshes the open page. New books read the persisted value rather than losing it with an activity-local override.
- User font CSS is injected with strong selector specificity and `!important` for reflowable EPUB content. Fixed-layout and image-page EPUBs continue to bypass forced reader typography.

## PDF app-chrome fullscreen

- PDF frame selection is now based on `pdfChromeVisible` in both orientations. Visible Readwide controls reserve their measured title/bottom-bar heights; hidden controls release those reserves and retain only Android status/navigation/display-cutout safe edges.
- PDF uses `EdgeToEdgeUtil.applyPdfSystemBarVisibility()`, isolated from the shared immersive-reader policy. Android status and navigation bars remain visible while Readwide's own controls toggle.
- The obsolete `pdf_nav_bar_spacer` remains zero-height and gone. A landscape side navigation rail is reserved through stable PDF-root side padding instead of a bottom spacer.

## No-rerender resize path

- A toolbar toggle does not call `renderCurrentPage()`, advance the accepted render generation, or clear the accepted page bitmap/cache.
- `setPdfViewportPadding()` invalidates only speculative geometry/prefetch work for the old frame. The already accepted bitmap is laid out in the new frame.
- `PdfPageView.prepareForViewportResize()` captures the normalized page point under the viewport center and the current fit-relative zoom. Fit pages adopt the new fit scale; zoomed pages restore that point and relative scale after `onSizeChanged()`.
- PDF continuous mode captures and restores its visible page/content ratio around the height change so a toolbar tap does not silently jump the list.
- Single-page rendering now requires both a positive content width and height before cache lookup or executor submission. An adapter-owned, bounded `postOnAnimation` retry is cancelled when display mode changes or the Activity is destroyed, replacing the old anonymous width-only retry.

## Pure policy checks

- `ReaderChromeLayoutMathTest` now records the chrome-dependent policy: hidden top/bottom use only system-safe edges; visible top/bottom prefer current complete measurements, then compatible cached values and fallbacks.

## EPUB chrome and image-page scroll correction

- Vertical-writing EPUB bookmarks now capture the first meaningfully visible sentence in logical right-to-left column order rather than the first Y-axis paragraph. App-bar-covered DOM ranges are excluded. Stable sentence element IDs are the primary restore key, followed by sentence/context text and block/offset range fallbacks; X-only scrolling schedules a fresh capture, a user gesture cancels the delayed font-settle re-alignment, and v1 anchors remain readable.
- Kusamakura exposed a second failure after that first fix: the candidate element and caret were selected by separate geometry passes, and Android WebView reported a 1536×2998 layout viewport for a 384×749.5 visual viewport. `DocumentContentAnchorJavascript` now probes a bounded right-to-left grid in the real visual viewport and derives the stable `span/p/li/blockquote` root from the caret at that same point. The v2 payload stores the caret's normalized X/Y focus and restores the text range to that screen position.
- The grid's edge probes keep a 24-48 CSS-pixel safe inset, and restore aligns the caret rectangle center rather than its `left/top` corner. Verification requires the whole glyph rectangle inside the safe frame with only subpixel tolerance. Short ID-less Japanese utterances remain semantic anchors, and `focusText` begins at the captured glyph instead of 24 characters earlier, correcting the real geometry bias.
- Overlay occlusion is converted from Android physical pixels to WebView CSS pixels before visible-sentence selection. This closes the density-dependent path where the top/bottom overlays consumed the entire DOM viewport and every Kusamakura save degraded to a page-start anchor.
- Explicit vertical saves now install the helper and capture in one WebView JavaScript evaluation, require a newly captured v2 sentence anchor, retry once after layout settling, and upgrade a same-page legacy page-only/v1 bookmark instead of leaving the obsolete row beside the new entry. A sentence-less publisher page can retain a signed-DOM `vertical-position` fallback; native-only offsets are rejected because vertical-rl WebViews can report zero while their DOM scroller moves. Same-page sentence offsets remain independent bookmarks, including during backup merge, and an explicit bookmark jump takes precedence over active find state.
- Restore work is bound to the original WebView/page/load/interaction generations before the 90ms delay. A same-viewport anchor reuses its exact signed DOM scroll, while a changed-viewport position fallback uses stored progress rather than raw coordinates. Sentence restores score ID-less duplicate candidates against the saved block/context, verify the exact glyph after the font-settle pass, force semantic glyph alignment if necessary, and verify that correction again before refreshing cached state. Early v2 anchors without `caretMatched` retain this robust restore path, but cannot be accepted as new precise captures.
- Rendered-document autosave now waits for its DOM capture and rejects callbacks from an obsolete page load. A same-page capture failure clears the stale semantic anchor instead of persisting an earlier horizontal column. Vertical bookmarks use sentence-level duplicate detection.
- Explicit fresh vertical bookmark capture alone enables a dense, presentation-only scan within the selected caret's physical column. The scan starts at the usable viewport top, accepts only fully visible glyphs within a narrow same-column tolerance, and stores `columnStartText` from the earliest visible glyph. Bookmark rows prefer that value, but the restore/dedup anchor (`elementId`, block/character offset, focus ratios, and scroll coordinates) is unchanged. Routine state capture avoids the additional scan.
- EPUB keeps Android status/navigation bars shown and gives their transparent edge-to-edge regions dedicated body-colored inset scrims. Icon contrast and legacy system-UI flags also derive from the body color, independent of Readwide toolbar visibility.
- EPUB alone now sets the normal-flow `document_top_page_status` row to `GONE`; Word, HWP/HWPX, and Markdown keep their compact hidden-chrome counter. The policy is reapplied after the asynchronous document type resolves, so the first EPUB page and `singleTop` replacements cannot retain the 32dp row.
- EPUB's `document_content_column` now owns stable Android top/bottom safe insets and the remaining side navigation inset. Status/navigation bars stay visible, and the safe frame remains identical while Readwide's app bars toggle; Haruko image pages can no longer extend into a punch hole or navigation controls.
- Chrome visibility changes no longer execute EPUB boundary JavaScript directly or through the bottom-bar layout listener. Boundary application remains tied to page loading, resume signature checks, and explicit boundary preference changes.
- Near-image-only fixed-layout pages are identified per spine item with stricter text limits than the established book-level spread decision. Fitting starts from the declared viewport and includes the real visible media bottom, but deliberately ignores publisher wrapper `scrollHeight`; this preserves scans that extend beyond imperfect metadata without inheriting a long empty wrapper tail. Image pages lacking usable viewport/viewBox metadata receive a viewport-sized nested-media `contain` fallback. The WebView root stays scrollable for zoom/pan.
- Text and short mixed image/article pages inside an image-heavy fixed-layout EPUB retain natural-height scrolling. The Find overlay keeps the same page-local overflow policy, and theme CSS preserves publisher `background-image` layers by changing only the body background color.
- `DocumentArchiveUtilsTest` covers page-local image/text separation, a short mixed page, and the 75%-image book case with a long textual minority page.

## IDPF image-spine and Japanese vertical EPUB compatibility

- `findEpubSpineItems()` is now manifest-aware: direct image spine entries are retained in OPF order, supported fallback chains are resolved with cycle/depth protection, and item/itemref rendition properties are preserved. `haruko-jpeg.epub` therefore produces its 13 intended image pages rather than falling back to the two auxiliary XHTML files.
- Direct raster image pages use header-only dimension probing and a synthetic local XHTML viewport. Resource names are URI-path encoded without converting literal `+` characters to spaces.
- `EpubCssCompatibility` adds WebView-compatible standard and WebKit declarations beside legacy `-epub-writing-mode`, `-epub-text-combine`, and `-epub-text-emphasis-*` declarations. Vertical books use the normal WebView layout algorithm and retain horizontal overflow and publisher column geometry instead of receiving Readwide's horizontal text-autosizing constraints.
- Vertical books also bypass generic cover centering and physical boundary injection so publisher cover placement and logical column padding are not overwritten.
- Landscape image spreads map logical pages to physical LTR/RTL slots and inward-align genuine image/image pairs with a total 12 CSS-pixel (about 12dp) seam. Aspect-ratio slack is moved to the outer edges; CSS background pages use the same slot policy, while mixed or single final pages stay centered.
- Global pre-paginated metadata can now be overridden by a spine item's `rendition:layout-reflowable`, preserving normal scrolling for a mixed book's long information page.
- Package-level fixed layout and item-level fixed pages are now separated during detection. In the absence of authoritative package metadata, one cover or a minority of viewport-bearing pages cannot promote the entire EPUB; this corrects `cole-voyage-of-life` while preserving its four local pre-paginated pages.
- Both forms of the supplied IDPF EPUB 3 sample set were audited off-device. All 45 packages resolve their supported spine resources without a missing entry. Explicit scripted pages now keep JavaScript enabled without temporary helper callbacks turning it off; validated OPF bindings use opaque local handler frames and manifest MIME routing. Seven OPF-linked SMIL documents (1,137 cues) feed foreground publisher-audio playback and DOM following, while the seven Georgia point CFIs resolve through itemref ID/numeric spine targeting. Remaining browser/SMIL/range-CFI, font-obfuscation, `linear=no`, and rendition-metadata limits are catalogued in `EPUB_COMPATIBILITY_AUDIT_1_0_16.md`.
- Scripted publications now rotate to a per-open synthetic origin, disable cookies, reject network/resource fallthrough and residual `..` paths, and prevent non-spine handler XHTML from becoming the top-level reader document. Binding-only parent pages remove publisher active-content entry points before enabling the sandbox frame, and only payload XML actually referenced by a rewritten object is URI-normalized.
- Primary/right WebView page-load generations guard all finish callbacks. Pending CFI/fragment state is cleared on replacement documents, vertical logical-start alignment yields to a cross-page target, temporary JavaScript restoration is page-checked, fallback resources own their own active/layout/overlay metadata, and SMIL playback waits for seek completion and bypasses the gesture page-turn lock.
- Reflow height, boundary, fast-scroll, and tap policies are page-derived. Haruko's final HTML information page clears legacy `height`/`max-height` caps on both `html` and `body` and fills the available WebView before scrolling normally.
- Mobile vertical-writing pages clear the publisher's short `28em` inline-axis cap and automatic top/bottom centering, and no longer receive Readwide's generic 22px body padding. Right-to-left horizontal overflow is retained so later columns remain reachable.
- A normal page turn in a `vertical-rl` chapter aligns the first body element to CSS logical block-start rather than physical WebView x=0. Y remains unchanged, initial/restored anchors are preserved, and a page-guarded 140ms retry covers late font or stylesheet reflow without touching a newer page.
- EPUB theme injection applies the reader paper color with `background-color`; it no longer resets publisher `background-image` resources on vertical or image-bearing pages.
