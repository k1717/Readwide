# Readwide 1.0.21 development changes

This note records the implementation delta from 1.0.20, grouped by subsystem.

## TXT loading, position and contents

- `ReaderActivityStartupController` selects short-edge display-cutout layout on Android 9+ before content inflation. This addresses the Galaxy S20 hidden-status-bar black strip without reversing the setting, changing body padding or changing page calculation. Device confirmation remains pending.
- `ReaderSearchController` contains allocation/regex-stack failures in optional match counts. Separate request tickets prevent a canceled same-query callback from clearing its replacement; failed counts stay unknown and can be retried.
- `ReaderContentsController` initially scrolls its list near the active heading. Typing cancels initial positioning; later filtering does not move the document or repeatedly recenter the list. Scan/edit/options tasks share submission-failure handling; rejected queued tasks are canceled, and worker allocation/stack failures reach current-dialog recovery. Accepted edits still finish after orderly closure.
- `ReaderLargeTextPartitionNavigator` handles executor startup/rejection as well as read failures. Current failure cleanup releases the pending switch, queued page intent and loading state without replacing the visible text. Obsolete failures cannot clear a newer request.
- `SearchOptionsDisclosure` folds occurrence navigation and detailed TXT/document search conditions without changing listeners, matching, counts or persistence. Saved active conditions open expanded and appear in the folded summary.
- `ReaderBookmarkActionController` and TXT annotation creation require current loaded-source/transform ownership. Annotation offsets use long intermediates and saturate at the existing storage boundary instead of wrapping.
- TXT exact paging, partition sizes/overlap, half-visible-row selection and existing bookmark coordinates are unchanged. Empty TXT bookmark lists use the existing fixed-height list area.

## Reading-state and annotation persistence

- `CoalescingSnapshotWriter` releases identity-owned work after capture, encode, sink or submission allocation/stack failures. It does not retry an unchanged failed revision indefinitely; later requests/checkpoints may retry.
- `BookmarkManager` contains resource failures at best-effort lifecycle/bookmark save boundaries while retaining checked import propagation, lock ordering and revision precedence. Deferred copying precedes timestamp mutation.
- Portable bookmarks keep a readable, matching original binding when another identical copy is opened. Missing/replaced originals can relocate; saved fingerprints require a readable matching target. Legacy size/name and URI behavior remain.
- `DocumentAnnotationManager` publishes manual add/update/delete candidates only after atomic storage succeeds and returns detached rows. Note edits preserve current path/coordinate metadata, including edits opened before relocation. Failed note/delete dialogs remain available for retry.
- These changes do not make all model mutations transactional or guarantee saving under sustained resource exhaustion. Rename-reference persistence retains its existing best-effort behavior.

## File operations and external opening

- `FileMutationGuard` compares canonical parent, regular-file identity, size and available modification/change timestamps without adding content-hash checks. Android reads validate both paths and opened descriptors; API 27+ nanosecond access is gated, with path millisecond checks retained on API 24–26.
- `ReaderTextDisplayRuleDialogController` uses reporting encoding, owns temporary output through write/close failure and serializes physical edits. Source checks surround decoding/transformation/replacement. Existing copy targets are captured before work; changed/new targets reject publication, while unchanged intentional replacement remains supported.
- `FileSystemOps` checks copied entries before fallback-move removal and deletes the captured inventory children-first rather than traversing a fresh source tree. Added/changed entries are retained; `MainClipboardController` refreshes partial results and moves saved references only after success.
- `MainActivity` and `SafBrowserActivity` resolve provider metadata off the UI thread. Generations, pause/navigation/destruction cancellation and queue cleanup reject late opens without growing replacement workers. Providers that ignore interruption can still occupy their worker.
- `UriOpenRequest` and `DocumentPageLoadController` share recognized document MIME suffixes, including legacy Word. Supported filenames retain precedence. The existing external-open filter also advertises supported Word/HWP/HWPX aliases; permissions and exported components are unchanged.
- Metadata checks cannot atomically exclude external writers. Last-check-to-rename/unlink races and edits hidden by timestamp precision remain possible.

## Settings and backup recovery

- `PrefsManager.resetReaderAndAppSettings` checks commit success, rolls back only its resettable key set and surfaces rollback failure. Language/theme application, success feedback and recreation follow a successful reset.
- `SettingsBackupViewModel` contains allocation/stack failures in work and submission and releases global operation ownership. `BackupImportTransaction` attempts every started step's reverse undo, including the partially applied step, while retaining original and cleanup failures.
- `AtomicUtf8File` aborts unfinished writes. Recovery is best effort under continuing exhaustion; there is no new backup-size cap or cross-file power-loss journal.
- EPUB alignment, independent text size and line spacing join typed preference validation, backup/import and reset. Old replacement backups migrate their shared size; old merged backups preserve the current independent EPUB choice.

## EPUB typography and controls

- `EpubTextAlignment` adds Book default, Left / start-aligned and Justified. `EpubTypography` keeps finite text-size normalization and the existing 50–267% zoom range, with Book default or 120–200% line spacing in 20-point steps.
- `PrefsManager` captures the old shared size before a TXT size change, first EPUB access or export. Both theme-signature branches include the independent preferences; changes use existing position-preserving reload ownership.
- `EpubCssCompatibility` uses its lexical declaration walker for literal alignment/line-height substitutions with original-value fallbacks and priority. Explicit center/right/end and protected heading/table/code/figure/navigation/quotation/poetry declarations remain intact. Book default installs no override; the existing 1.55 spacing fallback remains where book CSS supplies none.
- Fixed/image pages retain text scaling; fixed/image/vertical pages do not activate paragraph overrides. Actions recheck eligibility when selected. Font shorthands, expressions, escaped values, legacy alignment attributes and mixed writing modes are not fully interpreted; protected blocks can still inherit surrounding formatting.
- Settings alignment/spacing and reader font/alignment/spacing reuse rounded, bullet-free selection rows. EPUB More keeps minus/current size/plus/reset available for repeated adjustment. Option dialogs retire on controller closure.
- Text zoom and reset resolve each spread pane's own page, so a fixed-layout primary page does not suppress scaling in a reflowable neighbor. `epubReadingSystemJavascript` reports `BuildConfig.VERSION_NAME`.

## EPUB counters and progress

- `formatDocumentPageStatusLabel` supplies numeric ranges to both EPUB counters while accessibility, movement, file information and new fallback bookmark labels retain section descriptions. The normal-flow top row remains hidden; no new row changes the viewport.
- `EpubSectionProgressMath` uses native scroll offset, rounded CSS height times scale and viewport height. Horizontal, reflowable, ready single-pane sections can show `3 (42%) / 20`; partial values stay below 100 while downward scrolling remains possible.
- Loading/restoring, active slider previews, non-scrollable content and fixed/image/vertical/spread layouts omit the percentage. A verified local load may expose `about:blank` because its history URL is null; this is accepted only after current-load readiness/restore checks.
- Scroll, scale, layout, accepted load, restore and chrome events coalesce into one frame update. No polling, new script or page scan is added. A content-height change without an observed event refreshes on the next interaction.
- Counts remain loaded document sections, not screen pages, printed pages or semantic chapters. Section indices, spread arithmetic, slider mapping, existing excerpts and bookmark coordinates are unchanged.

## EPUB contents and note navigation

- `DocumentArchiveUtils.EpubPackageResources` identifies EPUB 3 navigation and the NCX referenced by `spine@toc`. `EpubNavigationParser` preserves nested order, resolves local paths once and filters targets to loaded sections; unusable navigation falls back to section order.
- `EpubNavigationController` owns searchable rounded contents and note popups. Contents initially positions near the current source section, not an inferred fragment. Notes accept semantic note blocks or marked references and show selected text, paragraph breaks and image alternative text without scripts, styles or marked backlinks.
- Marked references may use an empty anchor's immediately following paragraph/list item/aside, but cannot cross headings, prose or another named target. Ordinary unmarked links retain existing navigation. Popup dismissal does not move either pane.
- Parsing uses document-executor tasks and `DocumentZipSession` leases. Lease allocation precedes reader-count admission. Submission/worker failures use the existing section/link fallback only for the current session, dialog, pane, interaction and scroll; retired requests stay canceled. Reopening fallback Contents retries parsing.
- `EpubNavigationXml` converts standard HTML4 named characters in a bounded lexical pass, preserving XML escapes, comments, CDATA and processing instructions. External DOCTYPE declarations are removed locally; internal subsets and external resolution are rejected. Remote, absolute, root-escaping and malformed paths are not admitted.
- Optional cover/navigation/note parsing contains recursive DOM stack failures. Rich/dynamic notes, package-CFI contents, unavailable/non-spine contents targets, EPUB page lists and general Back history remain outside this implementation.

## Document loading, positions and scripts

- `DocumentPageLoadController` contains adoption/render-preparation failures, revokes save eligibility and retires partial resources only for the matching document generation. `ParsedDocument` transfers ZIP ownership once; replaced WebViews and invalidated page loads cannot complete a newer load.
- Explicit contents/link destinations wait for the correct ready pane, replace older pending destinations and retire earlier restore/logical-start/fixed-layout retries. Explicit cross-section navigation bypasses swipe debounce.
- `NativeDocumentViewport` and runtime anchor ownership reject captures spanning native movement, geometry, pane, page or interaction changes. Small native scrolls schedule refresh. Bounded save/bookmark retries retain previous successful progress when a fresh capture remains unstable.
- Semantic caches require an accepted ready load. Unmoved pre-reflow anchors and explicit pending restores remain authoritative. Native recreation coordinates stay in instance state, require compatible geometry and retain save protection through a pending reload; durable anchor formats do not change.
- App-controlled restore/link/search/read-aloud scrolling invalidates earlier captures even for DOM-only movement. Delayed search reveals retain their original view/load/query/ordinal/interaction and cannot override a newer touch or result.
- `DocumentJavascriptExecutor` shares temporary-script ownership within each pane load. Nested continuations run before release; duplicate callbacks, callback exceptions and rejected submissions settle once. Reload/invalidation/destruction retire old ownership without changing required-script policy.
- Missing renderer callbacks retain temporary permission until load retirement. Unobserved book-driven DOM movement, rotation-induced native clamping and continuing WebSettings/resource failure remain runtime limitations.
- Markdown accepts every positive rendered height, including one-viewport content, removing stale extra pages after shrinkage. Unavailable heights retain the prior fallback; visual-page formulas are unchanged.

## PDF, image and archive viewing

- `SequentialArchiveImageReader` lazily retains its 64 KiB copy/drain buffer under the existing session lock. Sensitive requests wipe the local buffer in `finally`; decoder retirement wipes/releases the field before close, even when cleanup must be retried. Cached/behind-frontier pages and cooperative yields retain their paths. Initial allocation still precedes decoder advancement. Lifecycle regression sources cover reuse, sensitive clearing, EOF, close failures and mid-entry failure.
- PDF menu zoom/reset targets the visible Matrix view in single/spread mode, retaining fit/maximum bounds, center clamping and delayed sharpening. A pending chrome resize captures the new scale. Continuous zoom and pinch/double-tap paths are unchanged.
- PDF/image slider accessibility and keyboard changes navigate immediately; touch moves remain preview-only until release. Programmatic updates do not navigate.
- Image counters share visible spread ranges and open numeric page entry guarded by sequence/source identity and current bounds. The field is 48 dp high, with 4 dp side margins and a 10 dp visible input/action gap; the popup is bottom-centered with a 12 dp offset. Configuration changes reapply its width and placement without losing input, and destruction dismisses it.
- `ViewerErrorPanel` separates errors from counters, clears obsolete callbacks and offers close plus safe manual retry. PDF retry distinguishes opening from rendering; changed archive sources cannot retry old entries.
- The failure card measures its action row first, then bounds only the scrollable message by the actual parent height. Expansion restores the preferred message height; existing button targets and rounding are retained. A window shorter than the actions themselves still cannot display the complete card.
- PDF spread-page rendering keeps bitmap cleanup around clear/open/render/close, including native-page acquisition failure. Success transfers ownership only after try-with-resources closes the page, preserving primary failures and existing white-paper dimensions/render mode.
- Local-image rename invalidates old-path work and resumes an unfinished requested decode while preserving healthy surfaces, zoom and accepted progress.
- `SequentialArchiveImageReader` retires partially advanced sessions after allocation/stack failure, attempts cleanup and preserves the original error. Failed cleanup remains retryable without immediately starting another decoder.
- Actual forward EOF now closes the underlying reader immediately after marking exhaustion, rather than retaining an unusable decoder until viewer closure. Cache/behind-frontier paths still precede the exhausted gate, and the session password remains available for independent fallback. Cleanup failure retains ownership for retry. Instrumentation sources cover EOF, checked/unchecked close retry, cooperative yield and verified sensitive-cache reuse. This does not eagerly scan beyond a successfully requested last image.
- Compressed TAR reads, header advancement and bounded skip calls observe interruption. Cancellation does not trigger fallback or drain unrelated tails. Free-space policy and extraction-size policy are unchanged.

## Archive compatibility

### RAR admission and mixed decoding

- `RarEntry.unpackVersion` survives snapshots. First-party compressed routes admit parsed generation 29 or existing internal unknown metadata, not other parsed generations; compressed split parts must match the head. Stored entries and native rewrites retain their routes. The [rardecode dispatch](https://raw.githubusercontent.com/nwaples/rardecode/master/archive15.go) supplies the generation contract; this does not add RAR1/2 decoding.
- `RarArchiveReader` advances over RAR4 packed extents, including LARGE words, before filtering unsafe names. RAR4/RAR5 reject dependencies on omitted compressed history and regular-file/directory-name conflicts, preserving earlier safe selected recovery.
- `RarSplitStoredPlan` admits solid-flagged stored RAR3/RAR4 splits through existing plain/AES input; stored data does not consume a compression dictionary.
- `Rar3PpmdSolidStreamDecoder` promotes at an internal LZ table to `Rar3ClassicLzEngine.decodeMixed`, replaying only the consumed mode byte. It retains the PPMd model, raw ring, current file offset, VM programs/queue and solid Huffman/match state. Return-to-PPMd blocks reuse the mutated model; pure PPMd and native preference retain their routes. The pinned [mixed decoder](https://raw.githubusercontent.com/nwaples/rardecode/76ac572a52e7550ccbbc75395d2e08e39c069e36/decode29.go) and [PPMd decoder](https://raw.githubusercontent.com/nwaples/rardecode/76ac572a52e7550ccbbc75395d2e08e39c069e36/decode29_ppm.go) document these state boundaries.
- `RarBitInput.hasBits` retains short prefetched prefixes at clean bounded-stream EOF without zero padding. Aligned byte reads share the reservoir; declared truncation and physical read exceptions remain terminal.
- Forward metadata snapshots preserve duplicate object identities for topology rejection. Plain/logical/PPMd plans retain history across dependent stored/directory members and release it after terminal verification and output closure. Decode, flush, payload, CRC, close and target-guard failures invalidate shared state; verified spools remain readable.
- `RarCanonicalHuffman.fromCodeLengths` accepts checked offset/count ranges with slice-relative symbols and no retained caller array. Classic table construction avoids four copies totaling 404 integers per rebuild. Whole-array and secondary-reader entry points remain; canonical lookup, short tails and table history use the same calculations.

### RAR VM boundaries

- `Rar3PpmdFilterOutput` executes the queue's private register snapshot directly. Admission still copies caller registers; standard filters read them and custom execution copies them into VM state.
- Explicit/reused zero lengths are allowed only for intermediate same-start stages with a queued predecessor. Each stage consumes its predecessor's result; the first raw region remains nonempty and owns overlap checks.
- `DeferredFilters` retains one bounded raw prefix only after complete preceding output, successful flush and explicit EOF, with a planned compressed solid successor. Starts rebase by consumed raw bytes without replaying them into the dictionary; branch offsets and the entire result belong to the receiving file.
- Incomplete preceding output, missing successors, late/overlapping schedules and standalone zero-input regions remain excluded. Selected plans cannot carry a partial prefix beyond the target. Complete runs require an empty pending queue before termination/independent reset and before output commit; failure/abort releases pending state.
- Classic and PPMd-starting paths pass `FileOperationProgress` into filtering. Custom VM work checks at the existing 1,024-instruction checkpoint and before persistent-state publication; chains check between stages and before output. The instruction budget and filter arithmetic are retained.
- The pinned [filter contract](https://raw.githubusercontent.com/nwaples/rardecode/76ac572a52e7550ccbbc75395d2e08e39c069e36/filters.go) supports zero-result chaining. [JunRAR](https://raw.githubusercontent.com/junrar/junrar/master/src/main/java/com/github/junrar/unpack/Unpack.java) and [rardecode](https://raw.githubusercontent.com/nwaples/rardecode/76ac572a52e7550ccbbc75395d2e08e39c069e36/decode_reader.go) do not establish completed-result splitting; oversized results are rejected before publication.
- UnRAR's inspected per-file pending-stack clearing differs from Readwide's conservative prefix-carry policy. Prefix carry remains a synthetic, producer-unverified profile. Live standard filtering uses `Rar3VmFilter`, not the legacy E8/E8E9 planning scaffold; no additional standard-filter arithmetic change is claimed.

### 7z origins, integrity and cancellation

- `SevenZStartHeader` finds prefixed content using start-header CRC, checked 64-bit bounds and bounded-memory cancellable scanning. The origin follows encoded/additional/main streams; packed ranges stay before the next header. Java/native encoded headers require exactly one folder, while ordinary file data can use multiple folders. Recognized 7z/CB7/numbered-split filenames are unchanged; stubs are neither recognized nor executed. See the public [metadata/range contract](https://raw.githubusercontent.com/ip7z/7zip/main/CPP/7zip/Archive/7z/7zIn.cpp).
- PPMd initializer/model/frequency/final-range/packed-EOF failures stay typed integrity failures through probing. LZMA/LZMA2 wrappers apply after property preparation, retaining physical input-error identity while classifying decoder corruption/truncation as terminal. `ExactStream`/`IntegrityStream` also reject clean EOF before a declared size. Unsupported options, cancellation, overrun and padding retain their distinctions; other generic codec/parser failures retain existing fallback.
- `SevenZBcj2Decoder` requires zero final range state before returning the last declared byte, including a buffered address byte. The array wrapper explicitly requests EOF so empty output validates the control header too. This follows the [BCJ2 finish contract](https://raw.githubusercontent.com/ip7z/7zip/main/C/Bcj2.h); conversion, lazy partial closure and raw padding policy remain.
- `FolderStream.drain` finishes decoded outputs in reverse topological order before packed bytes, including unused CALL/JUMP branches. Outputs bound directly to BCJ2 must return immediate EOF at their completion point; excess decoded bytes are not padding. Other coder read-ahead/draining and raw packed padding remain accepted. The public [BCJ2 wrapper](https://raw.githubusercontent.com/ip7z/7zip/main/CPP/7zip/Compress/Bcj2Coder.cpp) and [7z graph](https://raw.githubusercontent.com/ip7z/7zip/main/CPP/7zip/Archive/7z/7zDecode.cpp) define full finishing and decoded input sizes.
- Bulk extraction verifies zero-substream folders before visible output without decoding referenced folders twice. Selected/forward routes do not scan unrelated payloads. Drain checkpoints cover decoded tails, packed padding, EOF and verification.
- Encoded/additional metadata retains the operation token through allocation and at-most-64-KiB decoded reads. Raw-header reads have surrounding checks; individual blocking reads, codec and KDF calls are not preempted.
- Supported/unsupported probes share final validation; integrity/password failures remain terminal. Blocking pause checks precede source validation, followed by nonblocking cancellation checks. Final and intermediate folder cancellation clear verification before close can commit guarded files. No-stream empty files check cancellation before touching targets and source/token again before commit; earlier completed folders remain.
- `Source.check` requires the logical split input to remain usable even when path metadata is stable. The state check neither reopens files nor moves cursors; a retired physical source cannot trigger another backend.
- Packed-stream, output-guard and decoder-error-wrapper adoption close unregistered resources on failure, including a native LZHAM handle not yet owned by the graph. `RarOutputFileGuard` allocates before moving an original. `ArchiveSupport.openExtractionOutputStream` retains raw output ownership until buffering succeeds. Cleanup failures are suppressed on the original error; exhausted-heap recovery remains best effort.
- Verified forward-folder reads seek only when entering a member; later chunks use the private advanced cursor. Each read still validates spool length and member range, including empty members and transitions after partial/drained predecessors.

### LHA, EGG and ALZ

- `AlzObfuscatedDeflateInputStream` independently implements RFC-1951 framing with ALZ's entry-size-dependent dynamic code-length order. Nonnegative long sizes avoid signed-int modulo narrowing; standard fixed/stored blocks use a 32 KiB history, not an entry-size ceiling. Extraction and probes pass declared output size and progress, retaining exact length/CRC, split/ZipCrypto and rollback. Methods 0/1/2 retain their decoders. See [ALZ format notes](ALZ_FORMAT_NOTES.md).
- Method 3 lazily reuses fixed trees, constructs dynamic trees from checked ranges and batches only pending stored/match runs within existing 4,096-byte output checkpoints. Matches seed from old ring history before repeating initialized output, preserving overlap and wrap; scalar parsing and stored refill validation are shared. Invalid tables/repeats/references, truncation and source failures remain terminal. `AlzDecryptingInputStream` separately reuses one scalar-read byte and clears it on close.
- EGG recognizes bounded inter-file/block SKIP records. `readBlockDataOffset` accepts COMMENT/DUMMY/SKIP chains before block END only if the old missing-END successor is structurally impossible. Exact EOF or a recognized old successor retains legacy priority, even if deeper parsing later fails. The new branch requires END, checked packed extent and a recognized successor; it does not scan payloads or retry another interpretation after decoder failure.
- Unknown/ambiguous block extras and encrypted EGG filenames remain unsupported. Opaque global/prefix metadata uses bounded skipping, not decryption; [EGG format notes](EGG_FORMAT_NOTES.md#encrypted-filename-boundary) distinguish names from payload encryption. Store/Deflate/BZip2/AZO/LZMA and scoped ZipCrypto/AES/LEA block-owner paths retain their codec/cross-block state grammar.
- `selectAuthenticatedDecryptor` resolves distinct UTF-8/Windows-949 AES/LEA candidates that both pass the short verifier by checking full ciphertext HMAC over the owner's blocks, excluding intervening headers. It produces no plaintext/progress increment, leaves CTR fresh and resets MAC for extraction's own verification. A single match avoids the payload probe; non-ASCII passwords incur the additional candidate derivation.
- `SplitVolumeInput.SourceState` captures canonical physical identity, length and mtime before EGG prefix/ALZ framing reads. Resolvers validate parsing against that state; reader adoption cannot resample a changed baseline. `requireUnchanged` checks captured paths and active-handle length without moving cursors or opening extra handles. Single/raw-continuation windows and the plain-segment constructor used by split 7z retain their behavior.
- EGG/ALZ check source state around password candidates and file/block acceptance, including rejected candidates, earlier split parts and final progress callbacks. Full-MAC selection checks before buffer creation and after authentication; original physical failures keep priority. Pause waits precede validation and final cancellation checks do not wait afterward.
- EGG `SolidBlockSession` validates authenticated packed spools around encrypted-owner blocks. `SolidForwardReader` retains verified decoded-spool state through reads, drains, entry completion and replacement. Observable changes retire spools/input and restore pending output, retaining earlier verified files. Captured-set checks do not rediscover new volumes, lock sources or detect identical-metadata replacements/final-check races.
- `SolidEntryWriter` closes an unadopted current guard directly before restoring the pending list in reverse, without retrying failed list allocation. Duplicate filenames keep their rollback order. Cancellation checks cover total reporting for empty archives, final ALZ/ordinary EGG closure, and solid-file callbacks before opening trailing empty targets.
- EGG removes the unread cumulative `runningCrc`, retaining per-block CRC, the unspecified-zero rule, authentication, packed-tail cipher advancement and accounting. Shared EGG/ALZ/7z split input retires after physical I/O or unchecked access failure; sibling views cannot replay partial data.

#### Buffered decoding and cancellation

- `OwnedDeflateInputStream` receives EGG/ALZ tokens through positive reads and packed refills, including repeated empty-block chains and password probes. Invalid/zero-length call ordering, sticky source/cancellation failures and the tokenless ZIP/7z constructor are retained.
- `ArchiveBzip2InputStream` supplies one scoped 64 KiB buffer after integrity/decryption wrappers for EGG/ALZ/7z/ZIPX. It stays inside packed boundaries and retains Commons decoding, concatenated members, headerless ALZ handling and final CRC/MAC checks. Constructor failure leaves source closure with the enclosing container. See the [Commons decoder](https://raw.githubusercontent.com/apache/commons-compress/rel/commons-compress-1.28.0/src/main/java/org/apache/commons/compress/compressors/bzip2/BZip2CompressorInputStream.java) and [bit-input contract](https://raw.githubusercontent.com/apache/commons-compress/rel/commons-compress-1.28.0/src/main/java/org/apache/commons/compress/utils/BitInputStream.java).
- EGG LZMA observes tokens during preamble reads, before dictionary creation and around existing packed refills. XZ constructor initialization reads input; failed-construction source ownership remains with extraction/probe scope. Properties, dictionary sizing and block cipher continuity are retained.
- Trimmed ALZ BZip2 observes tokens at bit/output buffering, after successful refills and every 4,096 inverse-BWT positions. AZO checks framed preflight/copy, 64 KiB packed reads, raw decoding and x86 filtering; cancellation cannot choose raw fallback or another password candidate. Codec arithmetic and block-local history/filter state remain.
- Individual reads, allocations, array copies and third-party inner decode loops can delay cooperative cancellation. Platform Deflate, Commons BZip2, XZ LZMA/LZMA2 and existing native modules remain dependencies. ALZ trimmed BZip2 is Commons-derived; no independent standard BZip2 replacement is claimed.

#### PMarc stored entries

- Native LHA admits CRC-bearing level-0 `-pm0-` headers with normal header sums and equal packed/original sizes. Extended bytes are comments, not Unix metadata. `.pma` joins recognition/thumbnails without adding Amiga `.l01` association.
- PM1/PM2, other header levels, passwords and general multi-disc restoration remain excluded. The retained patch follows the public [method registry](https://raw.githubusercontent.com/fragglet/lhasa/master/lib/lha_decoder.c) and [header rules](https://raw.githubusercontent.com/fragglet/lhasa/master/lib/lha_file_header.c).

### Archive regression scope

The following describes regression source coverage, not executed results. Compile/runtime status is recorded once under [Validation boundary](#validation-boundary).

- RAR sources cover decoder admission/snapshots, plain/AES stored splits, PPMd↔LZ transitions, table-less successors, resets, metadata isolation, short Huffman tails and failure rollback. Keep-old table cases check all 404 lengths, match history and low-distance reset inside a file and after a solid PPMd member; their PPMd dispatch input is synthetic.
- VM sources combine range-coded bodies with seeded records, standard/custom chains, zero/resized intermediate results, raw history, deferred prefixes and terminal/reset rejection. Independent Audio adaptation/channel-reset and active Itanium bundle/tail expectations are not computed with the same primitive under test. Token cases preserve globals/execution counts and retire cancelled pending work. These are not producer-created cross-file-filter archives.
- 7z sources cover prefixed/split origins, encoded-header folder counts, solid/independent PPMd/LZMA2, skipped/unused-folder integrity and failed spools. BCJ2 cases include matching-CRC but unfinished control streams, empty/final-address output, unused compressed branches, nested Copy tails, extra decoded input and valid packed padding. Header/registry cases distinguish malformed properties, short output, payload errors, physical errors and cancellation.
- `SevenZForwardPositionTest` covers partial/unread/drained/empty members, AES split-solid input and changed spool length. Adoption/guard helpers cover registration/rename/close failure, original-error suppression and target restoration; they do not induce actual heap exhaustion or execute JNI.
- `AlzObfuscatedDeflateInputStreamTest`, `AlzipArchiveReaderTest` and `AlzPasswordProbeTest` cover size residues/large declared sizes, fixed/stored/dynamic transitions, overlap/window wrap, malformed data, sticky errors, scratch/tree reuse and output slices. Encrypted splits cover UTF-8/MS949 candidates, 16 KiB refills, 64 KiB output chunks, every 12-byte encryption-header cut, descriptor flags, password/CRC rejection, late volume changes and per-entry isolation. Unknown-method rejection uses method 4; these synthetic writers are not independent ALZip producer oracles.
- EGG sources cover SKIP/block-extra lengths and legacy successors, metadata-shaped payloads, encrypted split/solid ownership, empty final blocks, final CRC failures and target/spool/index preservation. Encrypted-name flag cases test rejection, not a filename cipher.
- `AlzEggSourceHandoffTest` resolves segments once before changing stripped framing, including missing parts, growth with restored mtime and raw continuations. Source/spool cases cover active/earlier volumes, unchanged cursors/caller buffers, pending rollback and verified-prefix retention. They use deterministic mutation, not a timing-based writer race.
- `EggAuthenticatedCandidateTest`, `EggSolidOwnershipTest`, `AlzipProbeSourceBoundaryTest` and `ArchiveCancellationBoundaryTest` cover full-MAC selection, fresh cipher state, physical-error priority, rejected candidates, duplicate-target recovery and pause/cancel ordering. Ambiguity is injected into already header-verified contexts, not demonstrated with a producer verifier-collision archive.
- Deflate, standard/trimmed BZip2, LZMA and AZO sources cover constructor/refill/buffered/EOF/skip cancellation, malformed counts, short reads, concatenated blocks and encrypted probe/split/solid success/failure. Reflection-based checkpoint tests do not establish cancellation latency or new compressed AZO coverage.
- Static REA inspection of Bandizip 6.29 and WinRAR 7.23 informed comparisons of VM signatures, table reuse, ALZ code-length ordering and bounded decoder ownership. Public format/FOSS contracts remain the implementation basis; no proprietary or restricted UnRAR implementation is included. These observations do not establish runtime compatibility or faster decoding.
- The [1.0.20 archive baseline](ARCHIVE_DECODE_BOUNDARIES_1_0_20.md) applies except for the additions/restrictions above. LZ4 duplicate-preflight removal remains deferred pending equivalent failure timing and linked-history validation; no codec replacement or complete archive compatibility is claimed.

## Read aloud and home screen

- Document read-aloud auto-start resets per loaded intent; polls/build results belong to that load. Failed text preparation releases current ownership without an automatic retry loop. PDF waiting follows the same failed-build boundary; explicit retry remains available.
- `TtsPlaybackBridge` accepts notification-body returns without reload only for the same live TXT/document/PDF host/path and no competing navigation. Explicit opens/bookmarks/start requests keep their load path and speech segmentation is unchanged.
- Pinned folders and Recently read headings increase from 12sp to 13sp while retaining 38 dp minimum rows, layout rules and spacing.
